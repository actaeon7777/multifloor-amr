# 엘리베이터 연동 RF 프로토콜 (nRF24)

- 문서 버전: 1.1 초안 (2026-10-21) — 열림 버튼 반복 누름(`repeat`) 추가. 예약 바이트를 쓰므로 프레임 `version`은 1 그대로
- RF 프레임 프로토콜 버전: **1**
- 대상 독자

  | 장치 | 하드웨어 | 볼 곳 |
  |---|---|---|
  | 홀 비콘 (각 층 엘리베이터 외부) | STM32F411 + nRF24L01+ PA+LNA, 배터리 | 전체 (§7 제외) |
  | 카 비콘 (엘리베이터 내부) | STM32F411 + nRF24L01+ PA+LNA, 배터리 | 전체 (§7 제외) |
  | AMR 하위제어기의 RF 부분 | NUCLEO-F446RE + nRF24L01+ PA+LNA | 전체 (§6은 상대 동작 이해용) |

- 상태: **AMR RF 노드 구현 완료**(비콘 없이 단독 검증), **비콘 미구현** (§12)

이 문서는 AMR과 엘리베이터 버튼 장치(비콘) 사이의 **무선 구간만** 정의한다. 비콘 담당자는 이 문서 하나만 보면 된다.
하위제어기가 받은 내용을 AMR 상위제어기(Jetson)와 CAN으로 주고받는 규칙은 [엘리베이터 RF 중계 CAN 프로토콜](ELEVATOR_CAN_PROTOCOL.md)에 따로 있다.
모든 장치는 이 문서의 값과 바이트 배치를 그대로 따른다. 다르게 구현해야 할 일이 생기면 먼저 이 문서를 고치고 버전을 올린다.

### 역할 분담

| 장치 | 책임 |
|---|---|
| 홀 비콘 | 1초마다 "나는 N층 홀 비콘"(PRESENCE)을 알린다. 직후 짧게 수신해 AMR의 호출 명령을 받으면 위/아래 버튼을 누르고 결과(RESULT)를 보낸다 |
| 카 비콘 | 1초마다 PRESENCE를 알린다(층은 알리지 않음). 층 버튼·"열림" 버튼 명령을 받아 누르고 결과를 보낸다 |
| AMR RF 노드 (하위제어기) | nRF24를 상시 수신 상태로 둔다. 상위제어기에서 받은 버튼 명령을 보관했다가, 대상 비콘이 깨어나 PRESENCE를 보낸 순간 COMMAND를 보낸다 |

- 비콘은 **문 상태를 알리지 않는다.** 문은 AMR이 LiDAR로 판별한다.
- 비콘은 **카 위치나 현재 층을 알지 못한다.** 카 비콘은 버튼을 누를 뿐이고, 도착 층은 AMR이 홀 비콘으로 판단한다.
- 언제 어느 버튼을 누를지는 AMR 상위제어기가 정한다. 비콘은 받은 명령이 자기 것인지 검사하고 누르기만 한다.

## 1. 요약

| 항목 | 값 |
|---|---|
| 무선 | nRF24L01+ (PA+LNA 모듈), 채널 78(2478 MHz) 기본, 1 Mbps, CRC 2바이트, 주소 5바이트 |
| 페이로드 | **고정 16바이트**, little-endian, 마지막 바이트 CRC-8/SMBUS |
| 메시지 | `0x01 PRESENCE`(비콘 → 모두), `0x10 COMMAND`(AMR → 비콘), `0x11 RESULT`(비콘 → AMR) |
| 비콘 전원 | 배터리. **1초마다 깨어나 PRESENCE 송신 → 15 ms 수신 → 잠듦** |
| 명령 전달 | AMR이 대상 비콘의 PRESENCE를 받으면 **3 ms 안에** COMMAND 송신 |
| 수신 세기 | nRF24에는 RSSI가 없다. AMR은 **RPD 1비트(> −64 dBm)** 만 쓴다 |
| 최악 응답 시간 | 명령 보관 → RESULT 수신 약 **1.5초** |

## 2. 메시지 흐름

```text
 [홀 비콘 1F–7F]      [카 비콘 E1]          배터리, 1 s마다 깨어남
        │  ▲               │  ▲
PRESENCE│  │COMMAND        │  │
  RESULT▼  │     nRF24 2.4 GHz
     ┌─────────────────────────┐
     │ AMR RF 노드 (하위제어기) │   상시 수신
     └─────────────────────────┘
```

### 2.1 PRESENCE (층 알림)

```text
홀 비콘                         AMR RF 노드
  │ PRESENCE (브로드캐스트, ACK 없음)
  ├────────────────────────────▶│ RPD 읽기 → 상위제어기로 전달
  │ 15 ms 수신 창                 │
  │ 잠듦                          │
  … 1000 ± 100 ms 뒤 반복
```

### 2.2 버튼 명령 (홀 호출 예)

```text
AMR RF 노드                                   홀 비콘 4F
  │ HALL_CALL 4F DOWN, cmd_seq=0x15 보관
  │            … 비콘이 깨어날 때까지 (≤ 1.1 s)
  │◀──────────────── PRESENCE (4F) ─────────┤
  │ 3 ms 안에 송신 모드로 전환                │ 15 ms 수신 창
  ├── COMMAND(cmd_seq=0x15) ─────────────────▶│ 하드웨어 자동 ACK
  │                                          │ 버튼 300 ms 누름
  │◀── RESULT(PRESSED, cmd_seq=0x15) ─────────┤ AMR 주소로, 자동 ACK
  │ 상위제어기에 "버튼 눌림" 전달               │ 잠듦
```

층 선택(`CAR_FLOOR`)과 "열림"(`DOOR_OPEN`)은 대상이 카 비콘인 것만 다르다.
카 비콘은 문이 열려 있거나 AMR이 카 안에 있을 때만 전파가 닿으며, AMR도 그때만 이 명령을 보낸다.

**열림 버튼 반복 (AMR이 내릴 때)**

AMR은 명령을 한 번만 보내고, 1초 간격 반복은 카 비콘이 자기 타이머로 한다. 비콘은 1초에 15 ms만 수신하므로, AMR이 1초마다 따로 보내면 한 번만 놓쳐도 간격이 흐트러진다.

```text
AMR RF 노드                                   카 비콘 E1
  │ DOOR_OPEN, repeat=10, cmd_seq=0x19 보관
  │◀──────────────── PRESENCE (카) ──────────┤
  ├── COMMAND(repeat=10) ────────────────────▶│ 하드웨어 자동 ACK
  │                                          │ 열림 1회째 누름 (300 ms)
  │◀── RESULT(PRESSED, repeat=10) ────────────┤ "열림 버튼 누르고 있어"
  │ 상위제어기에 BUTTON_ACK                    │ 이후 깨어날 때마다(≈1 s) 1회씩, 총 10회
  │                                          │ 10회째 뒤 스스로 멈춤 (무선이 끊겨도)
```

### 2.3 응답이 없을 때

| 단계 | 누가 | 동작 |
|---|---|---|
| 무선 한 번 | nRF24 하드웨어 | 자동 재전송 (ARD 500 µs, ARC 10회) |
| 비콘 깨어남 한 번 | AMR RF 노드 | 같은 COMMAND를 다음 PRESENCE에 다시 보냄. 명령을 받은 뒤 **2.5초** 까지 |
| 미션 | AMR 상위제어기 | 3초 안에 결과가 없으면 **새 `cmd_seq`로** 다시 누르게 함. 3회 실패하면 미션 실패 |

## 3. 무선 계층 (모든 장치 동일)

### 3.1 nRF24L01+ 레지스터 설정

| 항목 | 레지스터 | 값 | 비고 |
|---|---|---|---|
| 채널 | `RF_CH` | **78** (2478 MHz) | 현장 스캔 후 74–82 중 확정 (§9.1). 모든 장치 같은 값 |
| 데이터 속도 | `RF_SETUP` RF_DR | **1 Mbps** | 250 kbps는 클론 칩 호환 문제와 긴 송신 시간 때문에 쓰지 않는다 |
| 송신 출력 | `RF_SETUP` RF_PWR | 장치별 보정 (§9.2) | 기본: 비콘 1(−12 dBm 설정), AMR 3(0 dBm 설정). PA 이득이 더해진다 |
| CRC | `CONFIG` EN_CRC=1, CRCO=1 | 2바이트 | |
| 주소 폭 | `SETUP_AW` | 5바이트 (`0x03`) | |
| 자동 재전송 | `SETUP_RETR` | ARD=500 µs (상위 4비트 `0x1`), ARC는 메시지별 (§3.3) | |
| 페이로드 | `RX_PW_Px` | **16** (고정) | 동적 페이로드(DPL) 사용 안 함 |
| `FEATURE` | | EN_DPL=0, EN_ACK_PAY=0, **EN_DYN_ACK=1** | NO_ACK 송신용 |
| `DYNPD` | | 0 | |

- 1 Mbps, 16바이트 프레임의 송신 시간은 약 0.2 ms(프리앰블 1 + 주소 5 + PCF 9비트 + 페이로드 16 + CRC 2)다.
- 국내 2.4 GHz ISM 대역은 2400–2483.5 MHz이므로 채널은 **83 이하**만 쓴다(84 이상 금지). 채널 80(2480 MHz)은 BLE 광고 채널 39와 겹쳐 피한다.
- 모든 장치는 부팅 시 위 레지스터를 써 넣고 다시 읽어 비교한다. 다르면 무선을 쓰지 않고 오류 상태로 둔다(비콘은 `CONFIG_ERR`).

### 3.2 하드웨어 요구 (PA+LNA 모듈)

- 모듈 3.3 V는 MCU와 별도 레귤레이터에서 공급하고, 모듈 핀 바로 옆에 10–100 µF 전해 + 100 nF 세라믹을 단다. PA 송신 순간 100 mA 이상이 흐른다.
- 안테나는 금속 케이스·모터·전원 배선과 떨어뜨린다. AMR은 안테나를 하우징 밖으로 뺀다.
- SPI는 **mode 0**(CPOL=0, CPHA=0), MSB 먼저, **8 MHz 이하**. CSN·CE는 GPIO, IRQ(active low)는 EXTI 하강 엣지.
- **비콘:** IRQ 핀으로 STOP 모드에서 깨어날 수 있어야 한다. 주기 깨어남은 RTC wakeup 타이머를 쓰고, 시계는 LSE(32.768 kHz 수정)를 권장한다.
- **AMR 하위제어기:** SPI1은 IMU가 mode 3으로 쓰고 있다. nRF24는 별도 SPI(SPI2 또는 SPI3)에 연결한다(§7.1).

### 3.3 송신 방식

| 메시지 | 송신자 → 수신자 | 방식 | ARC |
|---|---|---|---|
| PRESENCE | 비콘 → 브로드캐스트 | `W_TX_PAYLOAD_NOACK` (ACK 요청 없음) | **0** |
| COMMAND | AMR → 비콘 | 유니캐스트, 자동 ACK | 10 |
| RESULT | 비콘 → AMR | 유니캐스트, 자동 ACK | 15 |

- PRESENCE는 NO_ACK로 보내고 **ARC도 0으로 둔다.** 일부 클론 칩(Si24R1 등)은 NO_ACK 비트를 반대로 해석하는데, ARC=0이면 그래도 재전송하지 않는다.
- 유니캐스트 송신 전에는 `TX_ADDR`와 `RX_ADDR_P0`을 상대 주소로 맞추고 `EN_AA` P0, `EN_RXADDR` P0을 켠다(자동 ACK 수신용). 수신 모드로 돌아가면 P0 수신을 끈다.
- 하드웨어 PID 중복 제거(같은 PID·CRC 재수신 폐기)는 그대로 쓴다. 응용 단계의 중복 판정은 §5.6, §6.3, §7.3에 따로 정의한다.

## 4. 주소 체계

주소 5바이트 = `{node_id, NET_ID[0..3]}`. 레지스터에 쓰는 순서(LSByte 먼저)로 적었다.
nRF24의 수신 파이프 2–5는 파이프 1과 상위 4바이트를 공유하므로, 모든 장치가 같은 `NET_ID`를 쓰고 `node_id` 1바이트로만 구분한다.

| 항목 | 값 |
|---|---|
| `NET_ID` | `C5 3A 96 6E` |
| 예: AMR #1 주소 | `11 C5 3A 96 6E` (RF24 라이브러리 uint64 표기 `0x6E963AC511`) |
| 예: 4F 홀 비콘 주소 | `44 C5 3A 96 6E` (`0x6E963AC544`) |

| node_id | 장치 | 비고 |
|---|---|---|
| `0x11`–`0x1E` | AMR | AMR #1 = **`0x11`** |
| `0x21` | 카 비콘 E1 | 엘리베이터 n번 = `0x20 + n` (현재 E1만) |
| `0x40 + floor_code` | 홀 비콘 (E1) | 1F **`0x41`** … 7F **`0x47`** (현재 1–7층). floor_code −8 ~ +20 범위 (`0x38`–`0x54`) |
| `0xB5` | 브로드캐스트 | PRESENCE 목적지 |

- `floor_code`는 건물 층 번호다(3층 = 3). 지하층은 음수(int8)다. AMR 층 설정(`floors.yaml`의 `beacon_floor_code`)과 같아야 한다.
- node_id로 `0x00`, `0xFF`, `0x55`, `0xAA`는 쓰지 않는다(프리앰블·잡음과 혼동).
- 엘리베이터가 2대 이상이 되면 홀 비콘 번호 규칙을 다시 정하고 문서 버전을 올린다.

### 수신 파이프

| 장치 | P0 | P1 | P2 |
|---|---|---|---|
| AMR (상시 PRX) | 송신 중에만 ACK 수신용 | 자기 주소 `0x11`, EN_AA=1 | 브로드캐스트 `0xB5`, **EN_AA=0** |
| 비콘 (수신 창에서만 PRX) | 송신 중에만 ACK 수신용 | 자기 주소, EN_AA=1 | 사용 안 함 |

## 5. 프레임 (버전 1)

### 5.1 공통 형식 (16바이트 고정)

| byte | 형식 | 필드 | 설명 |
|---|---|---|---|
| 0 | uint8 | `version` | 항상 `1`. 다르면 프레임 전체 폐기 |
| 1 | uint8 | `type` | `0x01` PRESENCE, `0x10` COMMAND, `0x11` RESULT. 그 밖의 값은 폐기 |
| 2 | uint8 | `src` | 송신 장치 node_id |
| 3 | uint8 | `dst` | 수신 장치 node_id, 브로드캐스트 `0xB5` |
| 4 | uint8 | `seq` | 송신 장치의 프레임 번호 (§5.6) |
| 5 | uint8 | `elevator_id` | `1` = E1 |
| 6 | int8 | `floor_code` | 메시지별 의미 (아래 표) |
| 7–14 | | 본문 | 메시지별 (아래 표). 예약 바이트는 **0으로 보내고 받을 때는 무시** |
| 15 | uint8 | `crc8` | byte 0–14의 CRC-8/SMBUS |

**CRC-8/SMBUS**: 다항식 `0x07`, 초기값 `0x00`, 반사 없음, 최종 XOR 없음. 검사값 `crc8("123456789") = 0xF4`.
nRF24 하드웨어 CRC가 있어도 응용 CRC를 따로 둔다. 같은 채널·주소를 쓰는 다른 장치나 펌웨어의 구조체 배치 실수를 거른다.

```c
uint8_t crc8_smbus(const uint8_t *p, size_t n) {
    uint8_t crc = 0;
    while (n--) {
        crc ^= *p++;
        for (int i = 0; i < 8; i++)
            crc = (crc & 0x80) ? (uint8_t)((crc << 1) ^ 0x07) : (uint8_t)(crc << 1);
    }
    return crc;
}
```

구조체로 다룰 때는 패딩이 생기지 않게 `__attribute__((packed))`를 쓰거나 바이트 배열로 직접 채운다. 다바이트 필드는 little-endian이다.

수신 측 공통 폐기 조건: 길이 ≠ 16, CRC 불일치, `version` ≠ 1, 모르는 `type`, `elevator_id` 불일치, 유니캐스트인데 `dst`가 자기 주소가 아님.

### 5.2 PRESENCE (`0x01`, 비콘 → 브로드캐스트)

| byte | 형식 | 필드 | 설명 |
|---|---|---|---|
| 2 | uint8 | `src` | 비콘 node_id |
| 3 | uint8 | `dst` | `0xB5` |
| 4 | uint8 | `seq` | 비콘 프레임 번호 (§5.6) |
| 6 | int8 | `floor_code` | 홀 비콘: 자기 층. **카 비콘: 0** |
| 7 | uint8 | `role` | `0` 홀, `1` 카 |
| 8 | uint8 | `flags` | §5.5 |
| 9–10 | uint16 LE | `battery_mv` | 배터리 전압 mV. 측정 전이면 0 |
| 11 | uint8 | `fw_version` | 비콘 펌웨어 버전 |
| 12 | uint8 | `rx_window_ms` | 이 PRESENCE 직후 여는 수신 창 길이 (기본 15) |
| 13 | uint8 | `tx_power` | 현재 RF_PWR 설정 0–3 (보정 기록용) |
| 14 | — | 예약 | 0 |

### 5.3 COMMAND (`0x10`, AMR → 비콘)

| byte | 형식 | 필드 | 설명 |
|---|---|---|---|
| 2 | uint8 | `src` | AMR node_id (`0x11`) |
| 3 | uint8 | `dst` | 대상 비콘 node_id |
| 4 | uint8 | `seq` | AMR 자체 프레임 번호. 같은 명령을 다음 깨어남에 다시 보낼 때도 같은 값 |
| 6 | int8 | `floor_code` | HALL_CALL: 호출 층(= 대상 홀 비콘의 층). CAR_FLOOR: 누를 층. DOOR_OPEN: 0 |
| 7 | uint8 | `command` | `1` HALL_CALL, `2` CAR_FLOOR, `3` DOOR_OPEN |
| 8 | uint8 | `direction` | HALL_CALL: `1` UP, `2` DOWN. 그 외: `0` |
| 9 | uint8 | `cmd_seq` | **명령 번호.** 상위제어기가 매기며, 재시도마다 새 번호다. 비콘은 RESULT로 그대로 돌려준다 |
| 10 | uint8 | `repeat` | **DOOR_OPEN 전용.** `0`·`1` = 한 번 누름. `2`–`15` = 약 1초 간격으로 그 횟수만큼 누름. 다른 명령은 0. (1.0에서는 예약 0) |
| 11–14 | — | 예약 | 0 |

### 5.4 RESULT (`0x11`, 비콘 → AMR)

| byte | 형식 | 필드 | 설명 |
|---|---|---|---|
| 2 | uint8 | `src` | 비콘 node_id |
| 3 | uint8 | `dst` | 명령을 보낸 AMR node_id (COMMAND의 `src`) |
| 4 | uint8 | `seq` | 비콘 프레임 번호 (PRESENCE와 같은 카운터, §5.6) |
| 6 | int8 | `floor_code` | **비콘 자신의 층** (PRESENCE와 같게: 홀은 자기 층, 카는 0) |
| 7 | uint8 | `command` | 받은 명령 그대로 |
| 8 | uint8 | `direction` | 받은 명령 그대로 |
| 9 | uint8 | `cmd_seq` | 받은 명령 그대로 |
| 10 | int8 | `cmd_floor` | 받은 명령의 `floor_code` 그대로 |
| 11 | uint8 | `result` | §5.5 결과 코드 |
| 12 | uint8 | `repeat` | 받아들인 반복 횟수 (COMMAND byte 10 그대로, 실패 결과면 0) |
| 13–14 | — | 예약 | 0 |

### 5.5 열거값

**command / direction / role**

| 이름 | 값 | 이름 | 값 |
|---|---|---|---|
| `CMD_HALL_CALL` | 1 | `DIR_NONE` | 0 |
| `CMD_CAR_FLOOR` | 2 | `DIR_UP` | 1 |
| `CMD_DOOR_OPEN` | 3 | `DIR_DOWN` | 2 |
| `ROLE_HALL` | 0 | `ROLE_CAR` | 1 |

**PRESENCE flags**

| bit | mask | 이름 | 1일 때 |
|---|---|---|---|
| 0 | `0x01` | `BOOT` | 부팅 후 10초 이내 (seq가 0부터 다시 시작했음을 알림) |
| 1 | `0x02` | `BATT_LOW` | 배터리 전압이 설정 임계값 미만 |
| 2 | `0x04` | `BUTTON_FAULT` | 버튼 출력 회로 이상 (자가진단 실패 또는 마지막 누름 실패) |
| 3 | `0x08` | `CONFIG_ERR` | 설정값·무선 레지스터 검증 실패. 이 상태에서는 명령을 수행하지 않음 |
| 4 | `0x10` | `HAS_DOOR_OPEN` | 카 비콘: "열림" 버튼 출력이 장착됨 |
| 5 | `0x20` | `HAS_UP` | 홀 비콘: 위 버튼 출력이 장착됨 |
| 6 | `0x40` | `HAS_DOWN` | 홀 비콘: 아래 버튼 출력이 장착됨 |
| 7 | `0x80` | — | 예약 (0) |

**RESULT 결과 코드** — `0x80` 미만이 성공이다.

| 값 | 이름 | 의미 | AMR 해석 |
|---|---|---|---|
| `0x00` | `PRESSED` | 버튼을 눌렀다 | 성공 |
| `0x01` | `DUPLICATE` | 같은 버튼을 최근에 눌러서 이번에는 누르지 않았다 (§6.4) | 성공 |
| `0x81` | `WRONG_DEVICE` | 이 비콘의 명령이 아님 (홀 비콘에 CAR_FLOOR, 층 불일치 등) | 실패 |
| `0x82` | `UNSUPPORTED` | 해당 버튼이 없음 (최상층 UP, 운행하지 않는 층, "열림" 미장착) | 실패 |
| `0x83` | `BUTTON_FAULT` | 출력 회로 이상으로 누르지 못함 | 실패 |
| `0x84` | `BAD_REQUEST` | 인자 오류 (HALL_CALL인데 direction 0 등) | 실패 |

### 5.6 seq 규칙

- **비콘:** 장치당 8비트 카운터 **하나**. 새로 만드는 PRESENCE와 RESULT마다 1씩 늘린다(255 다음 0). 같은 RESULT를 다시 보낼 때는 같은 번호를 쓴다.
  AMR은 장치별로 이 번호를 보고 중복(같은 번호 5초 안)과 역순(차이 128 이상)을 버린다. PRESENCE와 RESULT가 같은 번호를 쓰면 뒤에 온 것이 중복으로 버려진다.
- **AMR:** COMMAND의 `seq`는 AMR 자체 카운터다. 비콘은 이 값을 쓰지 않는다. 명령 식별은 `cmd_seq`로 한다.
- 부팅하면 0부터 시작하고 10초 동안 `BOOT` 플래그를 켠다. 재부팅 직후 번호가 이전보다 128 이상 "뒤"로 보이면 AMR이 최대 5초 동안 그 비콘을 무시할 수 있다. 정상 동작이다.

## 6. 비콘 동작 (STM32F411, 배터리)

### 6.1 깨어남 주기

```text
[STOP + nRF power-down]
   │ RTC wakeup (1000 ms + 균등 난수 −100…+100 ms)
   ▼
nRF power-up (Standby-I, 1.5 ms 대기) → 배터리 측정(필요 시) → PRESENCE 송신 (NO_ACK, ARC=0)
   │ TX_DS
   ▼
PRX, 자기 주소, CE=1 ── rx_window_ms(15 ms) ──▶ 창 종료: CE=0, power-down, STOP
   │ COMMAND 수신 (하드웨어가 자동 ACK)
   ▼
CE=0, power-down → 검증(§6.3) → 버튼 출력(§6.4) → nRF power-up → RESULT 송신(ARC 15)
   → 실패(MAX_RT)면 10–30 ms 난수 백오프 후 재송신, 총 3회 → power-down, STOP
```

- 주기에 난수를 섞는 것은 여러 홀 비콘의 PRESENCE가 계속 같은 순간에 겹치지 않게 하기 위해서다. 평균 1초를 유지한다.
- 수신 창은 PRESENCE 송신이 끝난 직후 연다. **창 밖에서는 아무것도 받지 않는다.** AMR이 PRESENCE를 보고 나서 명령을 보내는 이유다.
- 한 창에서 COMMAND는 하나만 처리한다. 버튼을 누르는 동안과 RESULT를 보내는 동안에는 PRESENCE 주기를 미룬다.

### 6.2 장치 설정 (플래시 저장, 설치 시 기입)

| 항목 | 홀 1F | 홀 2F–6F (각 층) | 홀 7F | 카 E1 |
|---|---|---|---|---|
| node_id | `0x41` | `0x42`–`0x46` (= `0x40` + 층) | `0x47` | `0x21` |
| role | 0 | 0 | 0 | 1 |
| elevator_id | 1 | 1 | 1 | 1 |
| floor_code | 1 | 2–6 | 7 | 0 |
| 장착 버튼 (PRESENCE flags) | **UP만** (`HAS_UP`, 0x20) | UP·DOWN (0x60) | **DOWN만** (`HAS_DOWN`, 0x40) | 층 1–7, "열림" (`HAS_DOOR_OPEN`, 0x10) |
| 허용 AMR | `0x11` | `0x11` | `0x11` | `0x11` |

- 최하층·최상층에 없는 방향 명령이 오면 비콘은 `UNSUPPORTED`(0x82)로 답한다. AMR은 이를 `0x311` DEVICE_REJECTED로만 알리고 BUTTON_ACK는 보내지 않는다.
- 운행하지 않는 층이 있거나 버튼 구성이 다르면 §9.4 현장 확인 결과로 이 표를 고친다.
- **AMR 쪽은 층 수에 따라 바꿀 것이 없다.**
  - 라우팅은 `0x40 + floor_code`, 카는 `0x21`로 정해진다.
  - 비콘 표는 16대(`ELEV_PEER_COUNT`)라 홀 7 + 카 1을 동시에 들어도 여유가 있다.

공통 설정: 채널 78, NET_ID `C5 3A 96 6E`, 주기 1000 ms ± 100 ms, 수신 창 15 ms, 누름 시간 300 ms, 같은 버튼 재누름 금지 2000 ms,
TX 출력(§9.2 보정값), 배터리 저전압 임계값(전지 종류에 맞춰 결정).

### 6.3 COMMAND 검증

아래 순서로 검사하고 처음 걸린 결과를 RESULT로 보낸다. 공통 폐기 조건(§5.1)이나 허용 AMR이 아닌 `src`는 **응답 없이 버린다.**

| 순서 | 조건 | 결과 |
|---|---|---|
| 1 | `CONFIG_ERR` 상태 | 응답 없음 |
| 2 | 같은 (`src`, `cmd_seq`)를 10초 안에 이미 처리 | 누르지 않고 **저장해 둔 RESULT를 같은 seq로 재송신** |
| 3 | 홀 비콘인데 `command` ≠ HALL_CALL, 또는 `floor_code` ≠ 자기 층 | `WRONG_DEVICE` |
| 3 | 카 비콘인데 `command` = HALL_CALL | `WRONG_DEVICE` |
| 4 | HALL_CALL인데 `direction` ∉ {1, 2}, CAR_FLOOR인데 `direction` ≠ 0 또는 `floor_code` = 0, DOOR_OPEN인데 `floor_code`·`direction` ≠ 0, DOOR_OPEN인데 `repeat` > 15, 다른 명령인데 `repeat` ≠ 0 | `BAD_REQUEST` |
| 5 | 해당 방향·층·"열림" 버튼 출력이 없음 | `UNSUPPORTED` |
| 6 | 출력 회로 이상 | `BUTTON_FAULT` |
| 7 | 같은 버튼을 2000 ms 안에 눌렀음 (다른 `cmd_seq`). **DOOR_OPEN은 제외** | 누르지 않고 `DUPLICATE` |
| 8 | 그 밖 | 누르고 `PRESSED`. DOOR_OPEN `repeat` ≥ 2면 첫 누름 직후 RESULT를 보내고 반복을 시작 |

순서 2는 COMMAND는 도착했지만 AMR이 하드웨어 ACK를 못 받아 다음 깨어남에 같은 명령을 다시 보낸 경우다. 두 번 누르지 않는다.

### 6.4 버튼 출력

- 버튼 접점에 병렬로 연결한 무접점 출력(포토MOS 릴레이 등)으로 누른다. 기계식 푸셔는 쓰지 않는다(전력).
- 누름 시간 300 ms(설정 200–500 ms). **시간은 하드웨어 타이머로 끊는다.** 메인 루프가 멈춰도 출력이 켜진 채 남으면 안 된다.
- 출력 핀은 리셋 시 꺼지는 쪽(풀다운)으로 배선하고 IWDG를 켠다. 부팅 중에는 출력을 켜지 않는다.
- 같은 버튼을 2초 안에 다시 누르지 않는다. **일부 엘리베이터는 켜진 층 버튼을 다시 누르면 호출을 취소한다.** 설치 전에 대상 엘리베이터에서 반드시 확인한다(§9.4).
- **열림 버튼 반복 (`repeat` ≥ 2):**
  - 첫 누름은 COMMAND를 받은 창에서 한다. 나머지는 이후 깨어날 때마다(약 1초) 한 번씩 누른다. 반복 중에도 PRESENCE와 수신 창은 그대로 유지한다.
  - 각 누름은 300 ms 하드웨어 타이머로 끊는다. 정해진 횟수를 마치면 무선 상태와 관계없이 멈춘다.
  - 반복 중에 새 DOOR_OPEN(다른 `cmd_seq`)이 오면, 남은 횟수를 새 `repeat`으로 다시 시작한다(연장).
  - 2초 재누름 금지는 열림 버튼에 적용하지 않는다. 열림을 다시 눌러도 호출이 취소되지 않기 때문이다. 대상 기종에서 §9.4로 확인한다.
  - `repeat` 15는 약 15초가 상한이다. 반복 중 MCU가 리셋되면 반복은 끝난다(부팅 중에는 출력을 켜지 않음).
  AMR은 3초마다 새 `cmd_seq`로 다시 누르게 하므로, 재누름이 취소로 이어지는 기종이면 이 문서와 AMR 재시도 규칙을 함께 바꿔야 한다.

### 6.5 배터리 추정 (실측 전 계산값)

| 구간 | 시간 / 주기 | 전류 (가정) | 전하 / 주기 |
|---|---|---|---|
| PRESENCE 송신 (설정 + 송신) | 0.35 ms | 120 mA (PA) | 0.042 mAs |
| 수신 창 | 15.2 ms | 25 mA (LNA 포함) | 0.38 mAs |
| MCU 동작 | 약 20 ms | 4 mA | 0.08 mAs |
| 대기 (STOP + 모듈 power-down + 레귤레이터) | 나머지 | 약 50 µA | 0.05 mAs |
| **평균** | | | **약 0.55 mA** |

- 2000 mAh 기준 약 3600시간(약 5개월)이다. 모듈·레귤레이터에 따라 크게 달라지므로 **설치 전 실측해서 이 표를 고친다** (§9.3).
- 소모의 약 70 %가 수신 창이다. AMR 응답이 충분히 빠르다고 실측되면 창을 줄인다(그때 `rx_window_ms`로 알린다).
- 배터리 전압은 분압 저항을 스위치로 끊어 두었다가 측정 때만 연결한다. 측정은 60초에 한 번이면 충분하다.

### 6.6 홀 비콘과 카 비콘의 차이

| 항목 | 홀 비콘 | 카 비콘 |
|---|---|---|
| PRESENCE `floor_code` | 자기 층 | 0 |
| 받는 명령 | HALL_CALL (자기 층) | CAR_FLOOR, DOOR_OPEN |
| AMR에서의 쓰임 | **층 판단 근거**(문 열림 + 강한 수신일 때) | 장치 생존 확인. 층 판단에 쓰지 않는다 |
| 설치 위치 | 홀 문 옆, 호출 버튼 근처 | 카 조작반 근처 |

## 7. AMR RF 노드 동작 (하위제어기 NUCLEO-F446RE)

상위제어기와의 CAN 교환(명령 수신, 이벤트·진단 송신)은 [CAN 문서](ELEVATOR_CAN_PROTOCOL.md)에 있다. 여기서는 무선 쪽 동작만 정한다.

### 7.1 하드웨어 (펌웨어 담당자 기입)

| 신호 | 핀 | 비고 |
|---|---|---|
| SPI | SPI2: SCK **PB13**, MISO **PB14**, MOSI **PB15** (CN10-30/28/26) | mode 0, 42 MHz / 8 = 5.25 MHz. IMU의 SPI1과 별개 |
| CSN | **PB12** (CN10-16) | GPIO 출력, 초기 HIGH |
| CE | **PB2** (CN10-22) | GPIO 출력, 초기 LOW |
| IRQ | **PB1** (CN10-24) | EXTI1 하강 엣지, 내부 pull-up, NVIC 우선순위 5 |

- SPI3는 기본 SCK가 PC10(E-stop 입력)과 겹쳐 쓰지 않는다.
- 현재 시험 보드는 §3.2의 디커플링 커패시터 없이 연결되어 있다. PA 송신 순간 전압 강하로 모듈이 리셋될 수 있어, 펌웨어가 1초마다 레지스터를 다시 읽고 다르면 다시 초기화한다(`elev_radio_lost_count`). 실차 설치 때는 커패시터를 단다.

**펌웨어 구성** (`Core/Src/nrf24.c` 드라이버, `Core/Src/elevator_rf.c` 프로토콜 코어. 둘 다 HAL에 의존하지 않음)

- `RF_Task`(FreeRTOS, `osPriorityHigh`)만 SPI2와 nRF24를 다룬다. IRQ EXTI는 thread flag로 태스크를 깨운다. 엣지를 놓쳐도 10 ms마다 IRQ 핀 레벨을 확인한다.
- PRESENCE → COMMAND 경로는 CAN을 거치지 않는다. CAN 보고는 큐에 넣고 CAN_Task가 보낸다.
- 대기 슬롯은 4개다. 대상 비콘마다 하나씩 쓰고, 넘치면 가장 오래된 명령을 REPLACED로 버린다.
- 비콘 중복 판정 표는 16개다.
- 한 번에 COMMAND 하나만 송신한다. 다른 비콘의 PRESENCE가 겹치면 그 비콘의 다음 깨어남에 보낸다.
- 지연 측정: IRQ 엣지부터 COMMAND CE 펄스까지 DWT로 재서 `elev_lat_last_us`/`elev_lat_max_us`에 기록한다.
- 디버거 시험 경로:
  - `elev_debug_cmd[8]`에 `0x210` 8바이트를 쓰고 `elev_debug_cmd_request=1` → CAN 수신과 같은 검증을 거친다.
  - `elev_debug_scan_request=1` → §9.1 채널 스캔(70–83, 채널당 100샘플)을 실행하고 결과를 `elev_scan_hits[14]`에 둔다.
  - 도구: `tools/estop_snapshot.py --prefix elev_ --write-bytes ... --write ...`

### 7.2 무선 상태

- 평상시 **PRX 상시 수신**: P1 = 자기 주소(`0x11`), P2 = 브로드캐스트(`0xB5`).
- COMMAND를 보낼 때만 PTX로 바꾸고, `TX_DS` 또는 `MAX_RT` 직후 PRX로 돌아온다.
- 송신 중에는 다른 비콘의 PRESENCE를 놓칠 수 있다. 정상이다.

### 7.3 수신 처리

1. `RX_DR` 인터럽트 → **수신 모드를 벗어나기 전에** `RPD` 레지스터(0x09)를 읽고 FIFO에서 16바이트를 꺼낸다.
   RPD는 유효 패킷을 받을 때 래치되므로 그 패킷의 세기다. 한 번에 FIFO에서 2개 이상을 꺼내면 어느 패킷의 RPD인지 모르므로 **약함(0)으로 본다.**
2. 공통 폐기 조건(§5.1) 검사. 실패는 수신 불량으로 센다.
3. 같은 (`src`, `seq`)를 5초 안에 이미 받았으면 버린다.
4. PRESENCE이고 그 비콘에 보낼 명령이 있으면 **3 ms 안에** COMMAND를 송신한다(§7.4). 상위제어기 전달보다 먼저 한다.
5. 상위제어기로 전달한다. 수신 후 **20 ms 안에** 내보내고, 늦어진 프레임을 쌓아 두었다가 보내지 않는다.

PA+LNA 모듈은 LNA 이득만큼 RPD 기준(−64 dBm)이 실제로는 더 낮아진다. 그래서 비콘 송신 출력을 현장에서 보정한다(§9.2).

### 7.4 명령 송신

```text
상위제어기 명령 수신
   │ 대상 결정: HALL_CALL → 0x40 + floor_code, CAR_FLOOR·DOOR_OPEN → 0x21
   ▼
대상별 대기 슬롯(1개)에 저장. 기존 명령이 있으면 새 명령으로 대체
   │ 대상의 PRESENCE 수신 → 3 ms 안에 송신
   ▼
COMMAND 송신 ─ MAX_RT ─▶ 슬롯 유지, 다음 PRESENCE에 재송신 (같은 seq)
   │ TX_DS (비콘 하드웨어 ACK)          명령 수신 후 2.5 s 초과 ─▶ 전달 실패, 슬롯 삭제
   ▼
RESULT 대기 (1.5 s) ─▶ 결과(또는 무응답)를 상위제어기로 보고
```

- 대기 슬롯은 대상 비콘마다 1개다. 2.5초 제한은 상위제어기의 재시도 간격 3초보다 짧아 같은 비콘에 명령이 쌓이지 않는다.
- **PRESENCE 없이 COMMAND를 먼저 보내지 않는다.** 비콘이 자고 있어 전달되지 않고 전파만 낭비한다.
- RESULT는 대기 중인 명령과 맞지 않아도(늦게 온 이전 `cmd_seq`) 그대로 상위제어기로 보고한다.
- `elevator_id`는 1(E1)로 채운다.

### 7.5 실시간성

PRESENCE 수신부터 COMMAND 송신 시작까지 **3 ms** 를 지켜야 한다. 비콘 수신 창(15 ms) 안에 하드웨어 재전송 10회(약 8.5 ms)가 끝나야 하기 때문이다.
CAN mailbox 대기처럼 막히는 경로에 RF 처리가 묶이지 않도록 별도 경로(높은 우선순위 인터럽트 또는 전용 태스크)로 구현하고, 실제 지연을 측정해 §12에 기록한다.

## 8. 시간 예산 (무선 구간)

| 구간 | 최대 | 근거 |
|---|---|---|
| 명령 보관 → 대상 비콘의 다음 PRESENCE | **1.1 s** | 주기 1000 ± 100 ms |
| PRESENCE 수신 → COMMAND 송신 시작 | 3 ms | §7.5 |
| COMMAND 전달 (재전송 포함) | 8.5 ms | ARD 500 µs, ARC 10 |
| 버튼 누름 | 0.3 s | §6.4. 열림 반복도 첫 누름 뒤 곧바로 RESULT를 보내므로 같음 |
| RESULT 송신 (재시도 포함) | 0.15 s | ARC 15, 백오프 최대 3회 |
| **합계** | **약 1.5 s** | 상위제어기 응답 대기 3 s 안 |

- 첫 깨어남에서 전달에 실패하면 AMR이 다음 깨어남(약 1초 뒤)에 다시 보낸다. 응답이 3초를 넘는 경우는 비콘이 연속 두 번 이상 전달에 실패했을 때다.
- 같은 버튼을 2초 안에 다시 누르지 않으므로(§6.4) 상위제어기의 3초 재시도는 실제로 다시 누른다.

## 9. 현장 보정과 설치 전 확인

### 9.1 채널 선택

1. AMR RF 노드를 PRX로 두고 채널 70–83을 돌며 채널마다 RPD가 1인 비율을 잰다(송신 장치는 모두 끈 상태). 엘리베이터 홀과 카 안에서 각각 수십 초 측정한다.
2. 74–82 중 RPD 비율이 가장 낮은 채널을 고르고, 모든 장치 설정과 §3.1 표를 고친다.

### 9.2 송신 출력과 RPD 보정

AMR을 아래 위치에 두고 대상 비콘 PRESENCE 100개 중 RPD=1 비율을 잰다. 목표에 맞을 때까지 비콘 RF_PWR을 바꾼다.

| 위치 | 대상 비콘 | 목표 | 측정값 |
|---|---|---|---|
| 같은 층 홀 대기 위치 (문에서 0.6 m) | 그 층 홀 | RPD=1 ≥ 90 % | |
| 카 안, 도착 층 문 열림 | 도착 층 홀 | RPD=1 ≥ 90 % | |
| 카 안, 문 닫힘 | 모든 홀 | RPD=1 ≤ 10 % | |
| 인접 층 홀 대기 위치 | 다른 층 홀 | RPD=1 ≤ 10 % | |
| 카 안 | 카 비콘 | PRESENCE 수신율 ≥ 95 % | |

목표를 동시에 맞추지 못하면 층 판단을 RPD 1회 값이 아닌 최근 N개의 RPD 비율로 하도록 문서를 개정한다.

### 9.3 배터리

비콘 한 대의 1주기 전류 파형을 측정해 §6.5 표를 고친다. 전지 종류와 저전압 임계값, 교체 주기를 정한다.

## 11. 범위와 한계

- **인증·암호화가 없다.** 같은 채널·주소·형식을 아는 사람은 버튼을 누르게 할 수 있다. 피해는 엘리베이터 호출에 그치지만, 운용 전에 v2에서
  메시지 인증(예: 공유 키 AES-CMAC 4바이트 + 재사용 방지 카운터)을 넣을지 결정한다.
- 엘리베이터 1대(E1), AMR 1대 기준이다. 여러 대가 되면 주소 규칙(§4)과 비콘의 허용 AMR 목록을 다시 정한다.
- 비콘은 버튼 램프(점등 여부)를 읽지 않는다. 눌렀다는 것은 출력을 켰다는 뜻이지 엘리베이터가 호출을 등록했다는 확인이 아니다. AMR은 실제로 문이 열리는지(LiDAR)로 확인한다.
- 수신 세기는 RPD 1비트뿐이다. AMR은 층을 세기만으로 정하지 않고 문 상태·미션 문맥과 함께 판단한다.
- 비콘은 1초에 한 번 15 ms만 수신하므로 명령 지연이 최대 약 1.1초다. 더 빠른 응답이 필요하면 배터리 수명과 맞바꿔야 한다.
- PA+LNA 모듈은 제조사·클론마다 이득과 전류가 다르다. 같은 모델로 통일하고 §9 보정을 장치마다 한다.
- 2.4 GHz Wi-Fi·BLE 간섭은 채널 선택(§9.1)과 재시도로만 대응한다.
