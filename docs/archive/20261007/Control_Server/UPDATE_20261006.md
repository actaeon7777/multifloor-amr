# 중앙 관제 업데이트 — 2026-10-06

Jetson의 PC 작업물 이식에 맞춰 웹 화면과 원격 명령을 업데이트한다.
현재 AMR에서 준비·시험한 적용본이며 실제 호스트 PC 배포 완료를 뜻하지 않는다.

## 변경

- 새 웹 화면: 자동 위치 찾기, 위치 검증 및 주행 준비 상태, 제어기 재시작 대응.
- 원격 `relocalize` 전달: 좌표 없이 요청 ID와 지도 버전을 전송한다.
- 지도 버전/내용 확인, 명령 만료·중복 방지 및 기존 목표·초기 위치·취소 유지.
- 위치 상태에도 통신 지연을 누적하고 2초 이상 오래된 READY는 해제한다.
- 테스트용 로컬 웹 API가 사용하는 순수 Python `amr_control.time_guard`를 vendor에 포함한다.
- 서버의 주소·포트·공통 인증 파일·FastAPI 실행 방식은 유지한다.

## 기존 호스트 PC에 적용

`control_server_update_20261006.tar.gz`와 `.sha256`을 호스트 PC의 `/tmp`로 복사한다.
다음은 기존 프로젝트가 `/home/kim/Control_Server`인 경우다.
AMR 주행을 종료한 상태에서 수행하고, 어느 명령이든 실패하면 다음 단계로 넘어가지 않는다.

```bash
cd /tmp
sha256sum -c control_server_update_20261006.tar.gz.sha256
cd /home/kim/Control_Server
.venv/bin/python scripts/serverctl.py stop
host_backup="../Control_Server_before_20261006_$(date +%Y%m%d_%H%M%S).tar.gz"
tar -czpf "$host_backup" vendor pytest.ini README.md
tar -tzf "$host_backup" >/dev/null
printf '복귀 백업: %s\n' "$host_backup"
tar -xzf /tmp/control_server_update_20261006.tar.gz -C /home/kim/Control_Server
.venv/bin/python -m pytest -q
.venv/bin/python scripts/serverctl.py start
.venv/bin/python scripts/serverctl.py status
```

묶음은 vendor 소스·웹 파일·pytest.ini·안내만 포함한다. `.venv`, `config/server.env`,
`.run`, 인증 토큰, Tailscale 설정을 덮어쓰지 않는다. 새 외부 런타임 의존성은 없다.
실행 전에 `AMR_ASSETS_DIR`가 별도로 지정돼 있으면 이번 프로젝트의
`vendor/amr_web_ui/web`을 가리키는지 확인한다. 서버가 다른 웹 경로를 읽으면 화면이 갱신되지 않는다.

노트북에서 `http://100.88.249.77:8081/robots/amr-01/`을 열고 새로고침한다.
AMR의 통합 스택·웹 API·remote_client가 모두 켜져 있어야 실제 상태가 표시된다.
‘자동 위치 찾기’ 버튼과 위치 검증 상태를 확인한다. 요청 접수는 위치 검증 성공을 뜻하지 않는다.
최초 연결 검증은 AMR의 `can_dry_run:=true` 실행 상태에서 수행한다.

## 복귀

호스트 관리 스크립트로 서버를 종료한 뒤 위에서 출력한 백업을 프로젝트에 복원하고 다시 시작한다.
AMR도 함께 구버전으로 복귀한다. 명령 만료나 접속 복구 뒤 이전 목표를 자동으로 재전송하지 않는다.

```bash
cd /home/kim/Control_Server
.venv/bin/python scripts/serverctl.py stop
# 아래 경로를 적용 전에 출력한 실제 백업 파일로 바꾼다.
tar -xzpf /실제/Control_Server_before_20261006_시각.tar.gz -C /home/kim/Control_Server
.venv/bin/python scripts/serverctl.py start
```
