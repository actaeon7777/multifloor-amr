실제 AMR 이전 및 실행 방법
작성일: 2026-10-06 | 배포본: amr_real_20261006
============================================================

현재 작업 중인 amr_ws의 저장된 최신 소스를 기준으로 만든 전달본입니다.
이전 20261004 압축본 대신 이번 압축본을 사용합니다.
대상 환경은 사용자가 확인한 Ubuntu 24.04 / ROS 2 Jazzy입니다.
Jetson Orin에서는 대상 장치에서 새로 빌드합니다. 이번 전달본의 실차 실행과
arm64 빌드는 아직 수행하지 않았습니다. Ubuntu 22.04 / Humble 환경이면
아래 Jazzy 명령을 그대로 진행하지 말고 환경에 맞는 포팅이 필요합니다.

1. 무엇을 옮기면 되나
------------------------------------------------------------
다음 세 파일을 USB 또는 scp로 AMR 컴퓨터에 복사합니다.

  amr_real_20261006.tar.gz
  amr_real_20261006.tar.gz.sha256
  AMR_실물_이전_실행방법_20261006.txt (이 문서)

HTML 문서도 같이 제공하며 브라우저에서 열거나 인쇄할 수 있습니다.
실행 코드와 이 문서 사본은 압축 안에도 있습니다.
ROS·시스템 라이브러리 설치에는 인터넷이 필요할 수 있습니다.

포함: 로봇 URDF/실행용 메시, CAN 송수신, 조이스틱/mux, EKF, AMCL,
TIM 자동 위치추정과 인터페이스, Nav2 플러그인, 지도, 웹 UI, 기록 도구,
패키지 테스트 및 가벼운 시뮬레이션 소스/설정/참고 자료.
제외: PC의 build/install, Isaac Sim 설치본, 생성 로봇 USD 자산,
과거 rosbag/로그/백업, Git 내부 데이터, 비교용 CAD 메시와 형상 보고서.
sim 폴더 일부는 기록 도구와 비교 테스트가 참조하므로 포함했습니다.
실물 명령에서는 Isaac Sim을 실행하지 않습니다.
stm32_main_code.c는 참고 소스이며 이 압축을 푸는 것만으로 펌웨어가
업로드되거나 ODrive 설정이 바뀌지 않습니다. 현재 STM32 프로토콜과
바퀴 지름/윤거/방향은 현장 장치와 일치해야 합니다.

2. 최초 1회: 압축 해제와 환경 확인
------------------------------------------------------------
AMR 컴퓨터에서 압축 파일이 있는 폴더로 이동한 후 실행합니다.
아래는 홈 디렉터리 아래 새 배포 폴더에 푸는 예입니다.
같은 이름의 폴더가 이미 있으면 그 위에 덮어쓰지 않습니다.

  sha256sum -c amr_real_20261006.tar.gz.sha256
  test ! -e "$HOME/amr_real_20261006" && tar -xzf amr_real_20261006.tar.gz -C "$HOME"
  cd "$HOME/amr_real_20261006"
  sha256sum -c SHA256SUMS.txt
  cd amr_ws
  uname -m
  cat /etc/os-release
  ls /opt/ros
  test -f /opt/ros/jazzy/setup.bash && echo "Jazzy setup OK"

Jetson이면 보통 aarch64, OS는 Ubuntu 24.04, ROS는 jazzy를 확인합니다.
이후 이 문서는 ~/amr_real_20261006/amr_ws 위치를 기준으로 합니다.
기존 ~/amr_ws는 보존하고, 기존 스택은 Ctrl+C로 종료합니다.
예전 amr 별칭은 다른 폴더를 가리킬 수 있으므로 여기서는 사용하지 않습니다.

3. 최초 1회: 의존성 설치와 빌드
------------------------------------------------------------
새 터미널을 열고 아래를 순서대로 실행합니다. 명령이 실패하면 다음 단계로
넘어가지 말고 해당 오류를 해결합니다. ROS Jazzy가 설치된 장치 기준입니다.

  cd "$HOME/amr_real_20261006/amr_ws"
  export PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
  unset PYTHONHOME PYTHONPATH CONDA_PREFIX
  source /opt/ros/jazzy/setup.bash
  sudo apt-get update
  sudo apt-get install -y build-essential cmake python3-colcon-common-extensions python3-rosdep python3-pil python3-numpy python3-scipy python3-yaml python3-pytest can-utils

rosdep을 한 번도 초기화하지 않은 장치에서만 아래를 실행합니다.
이미 초기화되어 있으면 이 한 줄은 건너뜁니다.

  sudo rosdep init

이어서 실행합니다.

  rosdep update --rosdistro jazzy
  rosdep install --from-paths src --ignore-src --rosdistro jazzy -y
  export CMAKE_BUILD_PARALLEL_LEVEL=2
  export MAKEFLAGS=-j2
  colcon build --base-paths src --symlink-install --parallel-workers 2 --cmake-args -DCMAKE_BUILD_TYPE=Release -DPython3_EXECUTABLE=/usr/bin/python3
  source scripts/env.sh
  ros2 pkg prefix amr_stack
  ros2 pkg prefix amr_tim_localization
  ros2 pkg prefix amr_web_ui

세 경로가 모두 이번 배포 폴더의 install 아래여야 합니다.
TIM은 PCL/OpenCV/OctoMap/Eigen 등의 빌드 의존성이 있으며 rosdep이 설치합니다.
컴파일 중 메모리 부족으로 killed가 나오면 병렬도를 모두 1로 낮춰 재시도합니다.
ROS 자체가 없으면 포함된 scripts/install_ros_jazzy.sh와 PORTING_JAZZY.md를
검토하여 Jazzy 설치를 먼저 완료합니다. OS/JetPack 변경은 별도 작업입니다.

4. 최초 연결: CAN, 라이다, 조이스틱 확인
------------------------------------------------------------
아래 명령도 AMR 컴퓨터에서 실행합니다.

  cd "$HOME/amr_real_20261006/amr_ws"
  source scripts/env.sh
  ip -details -statistics link show can0
  systemctl status can0.service --no-pager
  ls -l /dev/serial/by-id/
  groups
  ros2 run joy joy_enumerate_devices

CAN
  기존 정상 동작하던 can0 설정/서비스를 우선 사용합니다.
  소스에는 시스템의 can0.service나 udev 설정이 포함되어 있지 않습니다.
  과거 장치 기록은 500000 bit/s입니다. 실제 STM32도 이 속도를 쓰는지
  확인한 경우에만, 스택이 꺼진 상태에서 수동으로 다음처럼 준비합니다.

    sudo ip link set can0 down
    sudo ip link set can0 type can bitrate 500000
    sudo ip link set can0 up
    ip -details -statistics link show can0
    timeout 5s candump can0

  candump는 읽기만 합니다. 5초 후 timeout 종료 코드 124는 정상입니다.
  can0가 없으면 CAN 어댑터/드라이버/장치 설정부터 확인합니다.
  can0.service가 없더라도 수동 설정으로 CAN이 준비될 수 있습니다.

라이다 (S2)
  현재 설정 파일:
    src/sllidar_ros2/launch/sllidar_s2_launch.py
  serial_port 기본값:
    /dev/serial/by-id/usb-Silicon_Labs_CP2102N_USB_to_UART_Bridge_Controller_1805f83a4477ed119669f0fafdf7b791-if00-port0
  실제 ls 결과와 다르면 이 파일의 serial_port 기본 경로를 실제 경로로
  수정합니다. S2 기본 통신 속도는 현재 코드에서 1000000입니다.
  serial_port 인자를 experiment.sh에 추가하는 방식은 사용하지 않습니다.
  파일 수정 뒤 다음 명령을 실행하고 스택을 재시작합니다.

    colcon build --base-paths src --symlink-install --packages-select sllidar_ros2

조이스틱
  현재 이름은 Xbox Series X Controller이며 자동 선택합니다.
  ros2 run joy joy_enumerate_devices 결과의 SDL 이름이 다르면
  src/amr_system/amr_stack/config/joy_teleop.yaml의 device_name을 바꿉니다.
  또는 실행 명령 끝에 joy_device_id:=0처럼 실제 SDL 인덱스를 지정합니다.
  /dev/input/js0의 숫자와 SDL 인덱스가 항상 같다는 뜻은 아닙니다.
  다른 컨트롤러라면 LB/RB 버튼 및 축 인덱스도 /joy로 확인합니다.

권한 오류가 있을 때만 실제 장치의 소유 그룹을 확인해 계정을 추가합니다.
예를 들어 dialout/input 그룹이 필요한 환경에서는:

  sudo usermod -aG dialout,input "$USER"

그룹 추가 뒤 로그아웃/로그인해야 반영됩니다.

5. 첫 실행은 CAN 송신 없이 확인
------------------------------------------------------------
이 단계는 연결된 센서를 읽되 이번 송신 노드가 모터 명령을 보내지 않습니다.
다른 CAN 송신 프로그램이나 예전 주행 스택은 먼저 종료합니다.
dry-run도 라이다와 CAN 수신은 켜므로 장치 준비는 필요합니다.

터미널 1 — 실물 스택, CAN 송신 미리보기

  cd "$HOME/amr_real_20261006/amr_ws"
  ./scripts/experiment.sh real can_dry_run:=true

터미널 2 — 수신과 송신 모드 확인 (각 echo는 Ctrl+C 후 다음 명령)

  cd "$HOME/amr_real_20261006/amr_ws"
  source scripts/env.sh
  export ROS_DOMAIN_ID=7
  ros2 param get /cmd_vel_to_can dry_run
  ros2 topic echo /scan --once --field header
  ros2 topic echo /wheel/odometry --once --field header
  ros2 topic echo /imu/data_raw --once --field header
  ros2 topic echo /odometry/filtered --once --field header
  ros2 topic echo /system/time_health --once --qos-durability transient_local
  ros2 topic echo /cmd_vel_to_can/tx_preview

dry_run은 true여야 합니다. /system/time_health의 healthy가 true이고
각 센서 데이터가 계속 들어오는지 확인합니다. 수신이 없으면 echo가 기다리므로
Ctrl+C로 빠져나와 장치부터 확인합니다. LB/RB/축도 이 상태에서 검증합니다.
이후 터미널 1에서 Ctrl+C를 누르고 모든 노드가 종료될 때까지 기다립니다.
dry-run이 남아 있는 상태에서 아래 실송신 스택을 추가로 켜지 않습니다.

6. 매번 실행: 터미널 1·2·3·4
------------------------------------------------------------
터미널 1~4는 모두 AMR 컴퓨터에서 실행합니다. SSH 창 여러 개여도 됩니다.
다른 노트북은 브라우저만 열면 됩니다. ROS를 노트북에 설치할 필요는 없습니다.
공통값은 ROS_DOMAIN_ID=7, use_sim_time=false입니다.

[터미널 1] 실제 AMR 전체 스택

  cd "$HOME/amr_real_20261006/amr_ws"
  ./scripts/experiment.sh real

이 명령은 CAN 실송신 모드입니다. 기본 시작 모드는 MANUAL입니다.
켜지는 항목: 조이스틱, mux, CAN 송수신, S2 라이다, 로봇 TF, EKF,
지도/AMCL, TIM 자동 위치추정, 위치 검증, Nav2, 시간 상태 감시.
bringup/localization/navigation을 다른 터미널에서 다시 켤 필요가 없습니다.
위치 탐색 중에는 로봇을 정지해 둡니다.
기본 지도는 실제 G동 4층 maps/G_4_floor/4_floor_0522.yaml입니다.
다른 장소라면 그 장소의 지도 YAML/이미지를 준비하고 아래처럼 지정합니다.

  ./scripts/experiment.sh real map:="/실제/지도/경로/map.yaml"

위 대체 명령은 기본 실행을 종료한 뒤 사용합니다. 두 개를 동시에 실행하지 않습니다.
로컬 화면에서 RViz도 필요하면 기본 실행 명령 끝에 use_rviz:=true를 붙입니다.
RViz는 선택 사항이며 웹 UI만으로 실행할 수 있습니다.

[터미널 2] 웹 UI 서버

  cd "$HOME/amr_real_20261006/amr_ws"
  source scripts/env.sh
  export ROS_DOMAIN_ID=7
  ros2 launch amr_web_ui web_ui.launch.py use_sim_time:=false

AMR 컴퓨터의 브라우저: http://127.0.0.1:8080
같은 네트워크 노트북/태블릿: http://AMR의_IP주소:8080
AMR IP는 별도 셸에서 hostname -I로 확인합니다.
터미널 2는 서버 실행 상태로 계속 둡니다.

[터미널 3] 주행 데이터 기록

  cd "$HOME/amr_real_20261006/amr_ws"
  AMR_EXPERIMENT_MODE=real ./scripts/record_trial.sh real_first_trial

설정·파라미터 수집 뒤 '기록을 시작합니다'가 나오면 주행합니다.
저장: bags/한국날짜/한국시각_real_first_trial/
AMR_EXPERIMENT_MODE=real을 생략하면 기본 sim/도메인 107을 기록하므로
반드시 위 명령을 그대로 사용합니다. 이름은 영문/숫자/밑줄/하이픈으로 바꿉니다.
이 스크립트는 지정된 토픽을 기록하며 모든 토픽을 기록하는 것은 아닙니다.

[터미널 4, 선택] 상태 확인

  cd "$HOME/amr_real_20261006/amr_ws"
  source scripts/env.sh
  export ROS_DOMAIN_ID=7
  ros2 topic echo /control_mux/mode --qos-durability transient_local

MANUAL 또는 AUTO를 확인합니다. Ctrl+C 후 필요에 따라 하나씩 실행합니다.

  ros2 topic echo /localization/status --qos-durability transient_local
  ros2 topic echo /system/time_health --qos-durability transient_local
  ros2 topic echo /navigation/status --qos-durability transient_local
  ros2 topic echo /cmd_vel

7. 실제 조작 순서
------------------------------------------------------------
1) 조이스틱을 연결하고 LB/RB와 스틱을 놓은 상태로 시작합니다.
2) 웹에서 지도와 라이다를 확인하고 '주행 준비 완료'를 기다립니다.
   자동 위치 찾기는 회전/이동 없이 수행합니다. '위치 확인 필요'가 나오면
   정지 상태에서 '초기 위치' 모드로 실제 위치와 방향을 지정하고 검증을 기다립니다.
   초기 위치와 목표 위치를 혼동하지 않습니다.
3) 수동 확인: MANUAL에서 LB를 놓았다 다시 누르고, 누르는 동안 스틱을
   조금 움직입니다. 왼쪽 세로축은 전후진, 오른쪽 가로축은 회전입니다.
   LB를 놓으면 정지를 요청합니다. 최초 실차 확인은 낮은 속도로 수행합니다.
   현재 설정의 선속도 요청 상한은 1.00 m/s이고 바퀴 상한도 적용되므로
   처음부터 스틱을 끝까지 밀지 않습니다.
4) 목표 주행: 실제 위치와 지도의 정합을 확인한 뒤 '목표 지정' 모드에서
   목표를 클릭/터치하거나 드래그하여 도착 방향을 지정합니다.
   목표 모드의 탭은 즉시 목표 전송입니다. MANUAL이면 '출발 대기'로 보관합니다.
5) RB를 한 번 누르면 AUTO로 바뀌어 보관된 목표로 출발합니다.
   AUTO에서는 LB와 스틱으로 수동 개입되지 않습니다.
6) RB를 다시 누르면 MANUAL로 돌아가 정지를 요청합니다.
   기존 목표가 일시정지 상태로 남을 수 있으므로 재출발을 원하지 않으면
   웹에서 현재 목표도 취소합니다. 수동 재개는 LB를 놓았다 다시 누릅니다.
7) 조이스틱 연결이 끊기면 정지/MANUAL 복귀가 적용됩니다.
   브라우저를 닫거나 웹 서버만 끄는 것은 주행 정지 명령이 아닙니다.

8. 종료 순서
------------------------------------------------------------
1) RB로 MANUAL 전환하고 웹에서 현재 목표를 취소합니다.
2) LB를 놓고 실제 바퀴가 정지했는지 확인합니다.
3) 터미널 3에서 Ctrl+C → 기록 종료/저장 경로 출력까지 기다립니다.
   해당 실험 폴더의 bag/metadata.yaml이 생성되어야 정상 종료입니다.
4) 터미널 1에서 Ctrl+C → 전체 ROS 스택 종료를 기다립니다.
5) 터미널 2의 웹 서버와 터미널 4의 모니터를 Ctrl+C로 종료합니다.
비정상 움직임은 현장의 물리 비상정지 절차로 멈춥니다.

9. 자주 막히는 부분
------------------------------------------------------------
Package not found
  빌드 완료 여부와 이번 폴더에서 source scripts/env.sh 했는지 확인합니다.
  예전 amr 별칭이나 다른 workspace의 setup을 섞지 않습니다.

라이다가 안 나옴 / Permission denied
  /dev/serial/by-id 실제 경로, 권한, S2 포트 설정과 재빌드를 확인합니다.

센서 수신 대기 / 시간 상태 이상
  /scan, /wheel/odometry, /imu/data_raw, /odometry/filtered와
  odom → base_footprint TF가 필요합니다. use_sim_time=false를 확인합니다.
  실제 시계 점프 뒤 latched=true이면 시간/센서 문제를 해결하고 정지한 뒤:

    ros2 service call /system/reset_time_fault std_srvs/srv/Trigger '{}'

  success=true 이후 위치를 재검증하고 목표를 새로 지정합니다.
  복구 서비스를 반복 호출하는 것으로 센서 이상을 해결할 수는 없습니다.
  여러 컴퓨터에서 ROS 노드를 분산 실행할 때는 시간 동기화도 맞춰야 합니다.
  이번 안내처럼 ROS 전체를 AMR에서 실행하고 노트북은 브라우저만 쓰면
  노트북의 ROS/DDS 설정은 필요하지 않습니다.

지도는 보이는데 출발하지 않음
  '주행 준비 완료', time_health healthy=true, AUTO, 조이스틱 연결을 확인합니다.
  /cmd_vel이 0이면 /control_mux/status와 /navigation/status를 확인합니다.
  /cmd_vel이 있는데 바퀴가 안 돌면 dry_run, CAN 및 하위 제어기를 확인합니다.
  임의의 별도 노드로 /cmd_vel을 직접 발행하여 제어 경로를 우회하지 않습니다.

웹이 안 열림
  터미널 2의 오류, hostname -I의 IP, 같은 LAN 여부, 포트 8080 접근을 확인합니다.
  8080이 사용 중이면 port:=8081로 켜고 브라우저도 8081로 접속합니다.

다시 이전 버전으로 돌아가기
  이번 실행을 모두 종료한 뒤 보존한 이전 폴더의 환경을 새 셸에서 source하고
  이전 실행 절차를 따릅니다. 이번 압축은 기존 폴더를 교체하지 않습니다.

10. 이번 전달본 검증과 소스 이력
------------------------------------------------------------
FILE_LIST.txt: 포함 파일/크기
SHA256SUMS.txt: 압축 내부 파일 무결성
amr_ws/RELEASE.json: 원본 경로, 기준 커밋, 원본/배포 파일별 SHA-256
SOURCE_GIT_STATUS.txt: 저장된 변경/신규 파일 목록
BUNDLE_CHANGES.patch: 배포 사본에만 적용한 기록 스크립트 보완
VALIDATION.txt: 이 컴퓨터에서 수행한 포장/정적 검증 결과와 미검증 범위

기록 스크립트는 Git 없는 압축본에서도 중단되지 않도록 보완했습니다.
원래 작업 폴더의 소스는 변경하지 않았습니다. 기준 커밋만으로 최신 내용을
식별할 수 없으며 RELEASE.json의 파일 해시가 이번 사본의 기준입니다.
처음 받은 상태에서 SHA256SUMS 검증을 수행합니다. 현장 설정을 수정하거나
빌드한 뒤에는 일부 파일/파일 목록이 배포 시점과 달라지는 것이 정상입니다.

이 문서가 이번 실물 전달본의 실행 안내입니다. amr_ws/README.md는 기존
시뮬레이션 중심 문서이고, 과거 실차 검증 기록은 이번 사본의 실차 검증을
뜻하지 않습니다. 실물 설치/센서/주행 결과는 현장에서 따로 확인합니다.
