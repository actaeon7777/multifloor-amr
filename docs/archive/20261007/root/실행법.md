명령은 [중앙 관제 실주행 테스트](../docs/AMR_REMOTE_REAL_DRIVE_TEST.md), 실제 실패 근거는
[2026-10-06 분석 보고서](../../../../diagnostics/navigation_2026-10-06_remote/REPORT.md)에 정리했습니다.

2026-10-02 bag 분석 후 기본 자율주행 상한은 **0.40 m/s, 0.60 rad/s**로 조정했습니다.
전역·지역 inflation은 1.60m, 방향 정렬 참조 거리는 1.00m입니다.
설정을 반영하려면 RB로 MANUAL 전환해 정지한 뒤 navigation 터미널만 Ctrl+C하고 다시 실행합니다.
재시험 시작 때는 2D Pose Estimate로 위치를 잡고 지도·스캔을 확인한 뒤 navigation을 재시작합니다.
이 순서로 이전 좌표에서 누적된 전역 장애물 셀을 초기화합니다.
첫 번째 분석은 [주행 분석 보고서](diagnostics/navigation_2026-10-02/REPORT.md),
두 번째 bag의 벽 접근과 DWB 가중치 조정은 [DWB 튜닝 보고서](diagnostics/navigation_2026-10-02_trial2/REPORT.md)에 있습니다.
제어기는 기존 **RotationShim + DWB**입니다. 벽 비용·경로 비용·불필요한 회전 비용을 조정했습니다.
세 번째 bag의 직진 흔들림과 코너 정체에 맞춰 경로 방향 투영 0.50m, 예측 1.5초,
지역 목표 방향 비용과 회전 탐색 범위를 조정했습니다.
특히 정지 후 작은 회전 명령에 gyro 회전이 부족해 머무는 구간을 확인했습니다.
분석과 분리 시험은 [직진·코너 튜닝 보고서](diagnostics/navigation_2026-10-02_trial3/REPORT.md)에 있습니다.
다음 실험은 `AMR_EXPERIMENT_MODE=real ./scripts/record_trial.sh dwb_tracking`으로 설정과 실행 파라미터를 함께 저장하세요.
상세 DWB 후보 점수(`/evaluation`)는 기본으로 끕니다. 필요한 짧은 진단에서는 별도 navigation YAML에

Jetson의 브라우저에서는 `http://localhost:8080`, 같은 LAN의 PC/태블릿에서는
`http://<Jetson IP>:8080`에 접속합니다. 브라우저에는 ROS나 rosbridge 설치가 필요 없습니다.
외부 PC에서 ROS 브리지를 실행할 수도 있으며, 이 경우 PC와 Jetson 모두 `ROS_DOMAIN_ID=7`로 설정하고

- **초기 위치**: 로봇 위치와 방향을 지도에 클릭·드래그합니다. `/initialpose`를 전송합니다.
  지도와 스캔이 맞는지 확인한 후 **목표 지정**을 사용합니다.
- **목표 지정**: 이동 가능한 지도 위치를 **한 번 터치하면 바로 목표를 전송**합니다.
  누른 채 드래그하면 도착 방향도 지정합니다. 단순 터치는 현재 로봇 위치에서 목표를 향하는 방향을 사용하며,
  오른쪽 도착 방향을 직접 수정하면 그 값을 사용합니다.
- **지도 이동**: 드래그로 이동합니다. 휠·두 손가락·+/− 버튼으로 확대하고, 전체 보기로 복귀합니다.
  두 손가락 확대는 목표를 전송하지 않습니다.
- **주행 목표 취소**: 이 웹에서 전송한 현재 목표만 취소합니다. 취소 완료 응답을 확인합니다.
  수동 주행 정지나 하드웨어 비상정지 버튼은 아닙니다.
- 지도·AMCL·스캔·전역/지역 경로·지역 costmap·footprint를 기본 표시하고 전역 costmap은 선택 표시합니다.
- 현재 시험 구성에서는 MANUAL에 목표가 보관되며 RB로 AUTO에 진입하면 주행합니다.
  웹은 기존 조이스틱·주행 허용 정책을 변경하지 않습니다.
- 재접속할 때 목표를 자동 재전송하지 않습니다. 같은 웹 서버가 실행 중이면 현재 목표 상태를 다시 표시합니다.

웹은 RViz의 `/goal_pose`와 같은 목표 관리기에 공개 Action `/navigate_to_pose`로 연결합니다.
Action 응답으로 목표 접수·실패·도착·취소를 확인하며 `/cmd_vel`에는 발행하지 않습니다.

주황 화살표는 AMCL 위치·방향, 주황 타원은 위치 불확실성입니다.

`Invalid frame ID "map" ... frame does not exist`는 RViz config가 만드는 프레임이 아니라
**AMCL의 `map → odom` TF가 아직 없다는 뜻**입니다. `stack`과 localization이 실행 중인지
확인한 뒤, 지도 위 실제 차량 위치에서 **2D Pose Estimate**를 누르고 방향을 드래그합니다.
초기 위치 입력 전에는 이 로그와 로봇·스캔 표시 오류가 나올 수 있습니다.
지도는 Fixed Frame과 같은 `map` 좌표이므로 초기 위치를 지정하는 데 사용할 수 있습니다.
초기 위치와 정상 스캔·오도메트리 TF를 받으면 AMCL이 변환을 발행합니다.

```bash
ros2 run tf2_ros tf2_echo odom base_footprint
# 위 명령은 Ctrl+C로 종료한 뒤 다음 변환도 확인합니다.
ros2 run tf2_ros tf2_echo base_footprint laser
ros2 run tf2_ros tf2_echo map odom
```

두 lifecycle 노드는 `active`여야 합니다. `/map`과 `/scan`이 도착하고,
`odom → base_footprint → laser`가 연결되어야 초기 위치 입력 뒤 `map → odom`을 얻을 수 있습니다.
`map` Fixed Frame을 다른 값으로 바꾸거나 임의의 정적 `map → odom`을 추가하는 것으로
AMCL 위치추정을 대신하지 않습니다.

### RViz와 조이스틱 조작

1. RViz의 Fixed Frame은 `map`을 사용합니다.
2. **2D Pose Estimate**로 현재 차량 위치와 방향을 지정합니다. AMCL 초기 위치가 이미 지정되어 있으면 유지합니다.
3. **2D Goal Pose**로 목적지를 클릭하고 드래그해 도착 방향을 지정합니다.
4. MANUAL 상태에서는 목표를 보관합니다. **RB를 한 번 눌러 AUTO로 전환**하면 주행을 시작합니다.

| 조작·상황 | 동작 |
|---|---|
| RB를 다시 눌러 MANUAL 전환 | 정지하고 목표 보관 |
| 다시 RB로 AUTO 진입 | 현재 위치에서 재계획해 보관한 목표로 재개 |
| 일시정지 중 LB 수동 주행 | 수동 이동 가능, 재개 시 바뀐 위치 사용 |
| 새 목표 지정 | 이전 목표를 새 목표로 교체 |
| 아래 목표 취소 명령 | 실행·보관 목표 모두 삭제 |
| 조이스틱 연결 단절 | 정지·MANUAL 전환, 목표 보관 |
| 조이스틱 재연결 | RB를 놓았다 다시 눌러 AUTO 재진입 |
| 도착·최종 실패 | 목표 종료, 재주행하려면 새 목표 지정 |
| navigation 종료·재실행 | 이전 목표 자동 복원 없음 |

RB는 누르고 있는 동안만 허용하는 버튼이 아니라 **누를 때마다 모드가 바뀌는 토글**입니다.
기본 화면은 기존 Humble 환경에서 사용하던 경량 화면을 Jazzy에서도 유지합니다.
초기 위치 설정 중 발생하던 TF 교착 상태도 피하도록 `amr_rviz_plugins/SingleThreadedTF`를
기본 사용합니다. navigation launch가 설치된 플러그인 경로를 RViz에 자동 전달합니다.
변경 적용에는 터미널 3을 종료·재실행하면 됩니다. 기존 실행 명령은 동일하며,
저장한 사용자 RViz 설정에서도 `Transformation -> Current`의
`amr_rviz_plugins/SingleThreadedTF` 선택을 유지합니다.
목표를 보관하는 일시정지·재개에는 **RB**를 사용합니다. 실행·보관 목표를 완전히 삭제하려면:

```bash
ros2 service call /navigate_to_pose/_action/cancel_goal action_msgs/srv/CancelGoal "{}"
```

초기 위치를 다시 지정할 때도 먼저 RB로 MANUAL 전환해 정지한 뒤 **2D Pose Estimate**를 사용합니다.
지도와 스캔이 맞는지 확인한 후 RB로 재개합니다. 주행 중 초기 위치를 바꾸면 경로 좌표가 갑자기 바뀔 수 있습니다.

차량 둘레의 형광 초록 사각형은 **Robot Footprint**로, 차체 0.640×0.544m에 사방 0.02m 여유를 더한
충돌 검사 외곽입니다. 벽·장애물 주변의 색 띠는 **costmap inflation**으로 가까울수록 높은 비용을 뜻합니다.
1.60m inflation 전체가 통행 금지인 것은 아닙니다. 전역 계획은 반경 0.44m 원형 모델이므로
약 0.88m보다 좁은 통로는 계획할 수 없으며, 격자·센서 오차를 고려하면 추가 여유가 필요합니다.

차량 CAD 모델과 Global Costmap은 기본으로 꺼져 있습니다. 필요할 때 Displays에서 켤 수 있습니다.
초록 footprint와 LaserScan·경로·Local Costmap은 기본으로 표시합니다.

상태를 별도 터미널에서 조회하려면 다음을 실행합니다.

```bash
amr
ros2 topic echo /navigation/status --qos-durability transient_local
```

## 3. 조이스틱 수동 주행

```bash
amr
stack use_rviz:=true
```

RViz가 필요 없으면 `stack`만 실행합니다. 지도·AMCL·navigation은 수동 주행에 필수가 아닙니다.

| 입력 | 기능 |
|---|---|
| MANUAL에서 LB를 누른 상태로 스틱 조작 | 수동 주행 |
| LB 놓기 | 수동 정지 |
| 전후 스틱 `axes[1]` | 전진·후진 |
| 좌우 스틱 `axes[2]` | 좌회전·우회전 |
| RB | MANUAL ↔ AUTO 전환 |

AUTO에서 MANUAL로 돌아온 후에는 **LB를 놓았다 다시 눌러야** 수동 주행이 재개됩니다.
기본 요청 상한은 선속도 1.00 m/s, 각속도 0.80 rad/s이며, 바퀴 속도 제한에 따라 최종 명령은 줄어들 수 있습니다.

## 8. 기존 주행 시험 스크립트

**navigation을 종료하고 시험 스크립트를 하나만 실행**합니다.
1 m·90° 시험에는 실제 `stack`, 조이스틱, LiDAR, 휠 오도메트리, IMU 피드백이 필요합니다.

### 1 m 직진

터미널 1은 `amr` → `stack`, 터미널 2는 다음과 같습니다.

```bash
amr
python3 src/straight_1m_test.py \
  --output "diagnostics/straight_$(date +%Y%m%d_%H%M%S)"
```

MANUAL 상태에서 `ready_press_RB_once_to_start`가 나오면 RB를 눌러 시작합니다.
최대 명령은 0.10 m/s입니다. 도중에 RB로 MANUAL 전환하면 시험이 종료되며 보관·재개하지 않습니다.

### 왼쪽 90° 회전

```bash
amr
python3 src/rotation_90_test.py \
  --output "diagnostics/rotation_$(date +%Y%m%d_%H%M%S)"
```

MANUAL 상태에서 `ready_press_RB_once_to_start_left_turn`이 나오면 RB를 눌러 시작합니다.
최대 명령은 0.15 rad/s이며 IMU 적분 각도를 기준으로 정지합니다.

두 시험은 완료·중단 후 자동 종료합니다. 다시 시험할 때는 MANUAL로 전환하고 스크립트를 새로 실행합니다.
`--output` 폴더는 아직 없는 이름이어야 하며, 결과는 `result.json`과 `samples.jsonl`에 저장됩니다.

### 우회전 2초 ↔ 좌회전 2초 반복

```bash
amr
python3 src/auto_turn_test.py
```

AUTO에서 각속도 -0.20 ↔ +0.20 rad/s를 반복합니다. RB OFF로 멈추고 다시 AUTO에 들어가면 우회전부터 재시작합니다.
이 스크립트는 AUTO에서 실행하면 즉시 시작합니다. 명령만 볼 때는 7번의 CAN 미리보기 구성을 사용합니다.

## 9. 상태·위치·속도·센서 조회

각 터미널에서 `amr`을 먼저 실행합니다. 계속 출력하는 명령은 Ctrl+C로 끝내고 다음 명령을 실행합니다.

### 수동·자율 모드와 목표 상태

```bash
ros2 topic echo /control_mux/mode --qos-durability transient_local
ros2 topic echo /control_mux/status --qos-durability transient_local
ros2 topic echo /navigation/status --qos-durability transient_local
```

### 주요 토픽

| 토픽 | 내용 |
|---|---|
| `/joy` | 조이스틱 입력 |
| `/cmd_vel_manual` | 수동 속도 요청 |
| `/cmd_vel_navigation` | Nav2가 계산한 속도 |
| `/cmd_vel_auto` | 목표 관리 또는 시험 노드의 자율 속도 요청 |
| `/cmd_vel` | mux가 선택하고 바퀴 제한을 적용한 최종 속도 명령 |
| `/odometry/filtered` | EKF 상대 위치·방향 및 추정 선속도·각속도 |
| `/amcl_pose` | AMCL의 지도 기준 위치·방향 추정 |
| `/wheel/odometry` | 바퀴 피드백 기반 오도메트리 |
| `/imu/data_raw` | IMU 각속도·가속도 |
| `/scan` | LiDAR 스캔 |
| `/diagnostics` | CAN 수신·센서 상태 |
| `/plan` | Smac 전역 경로 |
| `/local_plan` | DWB 지역 궤적 |

```bash
# 최종 명령 / EKF 추정 속도
ros2 topic echo /cmd_vel
ros2 topic echo /odometry/filtered --field twist.twist

# 위치추정·원시 센서 메시지 한 번 보기
ros2 topic echo /odometry/filtered --once
ros2 topic echo /amcl_pose --once
ros2 topic echo /imu/data_raw --once --qos-reliability best_effort
ros2 topic echo /diagnostics --once

# 수신 주기
ros2 topic hz /scan
ros2 topic hz /wheel/odometry
ros2 topic hz /odometry/filtered

# 현재 TF 위치·방향
ros2 run tf2_ros tf2_echo map base_footprint
ros2 run tf2_ros tf2_echo odom base_footprint

# 실행 중인 노드·토픽·Nav2 활성 상태
ros2 node list
ros2 topic list
ros2 lifecycle get /amcl
ros2 lifecycle get /planner_server
ros2 lifecycle get /controller_server
```

현재 차량의 지도 기준 자세는 `map → base_footprint` TF, 현재 속도 입력은 `/odometry/filtered`를 사용합니다.
`/cmd_vel`은 측정 속도가 아니라 차량에 보내는 명령입니다.

## 13. 종료·재실행

목표 주행을 끝낼 때는 위 목표 취소 명령을 사용하거나 RB로 MANUAL 전환해 정지합니다.
전체를 종료할 때는 **navigation → localization 또는 SLAM → stack** 순서로 각 터미널에서 Ctrl+C를 누릅니다.

- 지도 작성 후에는 SLAM 종료 전에 지도를 저장합니다.
- localization을 재시작하면 2D Pose Estimate로 초기 위치를 다시 지정합니다.
- navigation을 재시작하면 주행 목표를 새로 지정합니다.
- 기본 경량 화면은 충돌이 재현된 Nav2 RViz 플러그인을 불러오지 않습니다. 목표 지정은 **2D Goal Pose**입니다.
- RViz가 비정상 종료하면 navigation도 종료합니다. RB로 정지한 뒤 navigation을 다시 실행하고 새 목표를 지정합니다.

[내비게이션 구현 결과](diagnostics/navigation_2026-09-29/IMPLEMENTATION.md)에 있습니다.
